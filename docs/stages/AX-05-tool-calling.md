# AX-05 — Tool Calling + Structured Output

목표: AI가 자연어 요청을 허용된 기능 호출로 연결하고, 정확한 수치는 서버 코드가 계산하도록 한다.

첫 업무: 승인된 차량/배터리 사건 통계 조회(운영 접근 불가 시 합성 데이터). `evcare-nestjs-msa` API 실제 계약·권한과 사건 집계 기준을 확인하고 기존 안전 경계를 유지한다.

## 실행
1. 현재 Ollama 모델이 native tool calling/구조화 출력을 지원하는지 합성 스키마로 확인. 미지원/불안정하면 승인된 로컬 후보 모델을 비교. 문자열 추출로 권한 검증 우회 금지.
2. 최소 1~2개 읽기 전용 통계 함수와 MCP 도구 연결 여부를 결정. FastAPI/Pydantic 또는 기존 TypeScript/Zod 방식으로 기간, 프로젝트/차량 범위, 요청 크기, 입력 스키마를 검사. 실제 값과 단위, 조회기간, 출처, 데이터 기준시점을 함수가 반환한다. LLM은 요약만 담당.
3. 도구 선택 → 서버 검증 → 실행 → 결과 해석 → 구조화 출력. 스키마 불일치·허용되지 않은 기능·모호한 질문·오류·시간 제한·반복 호출 상한을 적용한다. 임의 SQL이나 실장비·승인·제어 호출 금지.
4. 정상·잘못된 도구 선택·잘못된 인자·근거 부족·권한 오류·조작된 도구 응답·LLM 출력 오류 포함 고정 시험을 만든다(최소 20건 목표). 사람의 기대 도구/인자/결과와 실제 값 비교. 상태 변경/외부 전송 0 여부를 별도 확인.

## 완료 기준
- [ ] 실제 native 호출과 구조화 결과를 재현, 서버 계산 일치 확인
- [ ] 허용 목록/스키마/권한/호출 상한/실패 동작 검증
- [ ] 시험 분모와 도구 선택·인자·결과 일치율 기록
- [ ] 운영 또는 합성 범위 명확히 표시, 기존 서비스 회귀시험 통과

지속 성과: 직원의 반복 조회·분석 업무를 자연어로 전환할 수 있는 기반. 운영 권한 없이 실제 사내 사용 성과로 표시하지 않는다.


## V2 실행 순서 변경
이 단계는 MCP보다 먼저 진행한다. 최초에는 모델 API의 native function calling과 로컬 허용 함수로 구현하고 AX-04에서 같은 도구를 MCP로 노출한다. Python 타입, Pydantic JSON Schema, `async`/`await`, HTTP 타임아웃, SSE/취소, pytest 모의 호출 코드를 사용자가 직접 읽고 수정·실패 재현하도록 안내한다. Few-shot, 출력 스키마, context budget을 각각 비교하며 실패 시 서버에서 거부한다.
