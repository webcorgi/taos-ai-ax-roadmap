# AX-06 — n8n: 반복 보고 업무 자동화

첫 적용: 주간 개발·운영 보고 초안. 기존 홈페이지 문의 폼·GAS·시트·텔레그램을 변경하거나 시험 제출하지 않는다. Git/프로젝트 상태와 승인된 Sentry 집계만 읽는다.

## 실행
1. 실제 보고 담당자, 보고 주기, 기존 수동 시간, 정해진 양식, 승인자가 있는지 확인. 실제 반복 보고 업무가 없다면 허가된 다른 반복 업무를 선정해 기록하고 변경 범위를 승인받는다.
2. 공식 n8n self-host 문서, 라이선스 및 버전, 자원, 실행 데이터 보관/비밀 관리 확인. 별도 격리 환경, 내부 접속, 제한된 credentials. 외부 노드/웹훅 및 AI 외부 API 금지 기본.
3. 수동 트리거 → 승인 읽기 전용 자료 수집 → 규칙 기반 통계 → 내부 LLM 초안 → 스키마 및 출처 검사 → 로컬 검토함. 최초에는 자동 발송/게시하지 않는다. 정기 트리거는 사용자 승인 이후 실행. 비식별 workflow export는 버전 관리.
4. 동일 주차 실행의 중복 방지 키, 중간 실패·재시도·오류 저장, 재실행 시 동일 보고 유지. 입력 부족/권한 오류는 보고 실패 또는 보류. 사람이 최종 승인하고 수정 기록을 남긴다.
5. 수동 보고와 동일한 예제 업무를 비교. 최소 서로 다른 기간/재시도 포함 3회 재현 목표. 실제 시간/사람 수정/일치 필드를 기록. 운영 도입은 담당자 확인 및 승인 후.

## 완료 기준
- [ ] 반복 업무 및 담당자/기준/승인 경계 정의
- [ ] 정상·데이터 부족·실패 후 재실행·중복 실행 검증
- [ ] 발송·운영 변경·외부 유출 없음 확인
- [ ] workflow export와 수동 검증 방법, 사람 검수 결과, 반복 지표 기록

지속 성과: 보고 작성 시간, 수정 필요 건수, 기간별 처리량. 업무가 실제 사용되지 않으면 격리 시연으로만 표시.
