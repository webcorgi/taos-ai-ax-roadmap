# AX-02 — Ragas: RAG 품질 평가

대상: RAG `evals/`, `scripts/evaluate_search.py`, `scripts/evaluate_answers.py`와 별도 평가 실행 환경. 기존 고정 근거 평가를 교체하지 않는다.

## 실행
1. Ragas 공식 문서에서 선택 버전의 metric/API, 평가 LLM과 임베딩 요건을 검토. Python 3.12/의존성 충돌을 피하도록 별도 잠금 환경에 설치하고 평가자 모델·버전을 명시한다. 외부 호출 기본값 금지. 로컬/승인 내부 모델로만 구성; 판단 품질 미달이면 사람 검수를 우선한다.
2. 승인된 독립 질문 50개 이상 목표. 답변 가능/근거 없음/문서 충돌/시점 의존/권한 제한/영문 식별자와 한국어 질문. 개발 조정용과 변경하지 않는 독립 평가용을 분리한다. 원문/질문은 승인 내부 저장소, Git에는 합성 예제와 비식별 결과만.
3. 기존 API 응답에서 질문, 답변, 검색 문맥, 기대 답변, 출처/기대 행동을 평가 입력으로 변환. 근거 충실도, 답변 관련성, 문맥 precision/recall 등 선택 버전이 지원하는 항목을 평가한다. 무응답·보류는 일반 답변 점수와 구분. 평가 오류는 실패/미측정으로 기록.
4. 기존 검색 Recall@5와 출처 해시/보류 규칙을 독립 비교. 사람이 최소 20건 목표로 검수한 판정과 자동 평가자의 일치/불일치를 분석. 평가자 편향·모델 성능·문서 범위 제한 기록.
5. 동일 모델/데이터/설정에 대한 기준값을 저장. 변경 후 같은 독립 질문으로 재평가; 사전에 승인한 지표별 임계값과 악화 허용 범위를 사용. 기존 90% 검색 목표 미달을 숨기거나 분모를 바꾸지 않는다. 첫 적용에서는 관측/report-only를 우선하며 불안정한 점수로 자동 배포 차단 금지.
6. Langfuse에는 집계된 점수와 비민감 식별 정보만 연동(지원 버전 확인), 주기적 검증은 승인 후 03:00 배치와 충돌하지 않게 실행.

## 완료 기준
- [ ] 독립 질문 세트와 분모·정답·버전 고정
- [ ] 평가 성공·실패·보류/근거 부족 및 사람이 확인한 일치 건수 기록
- [ ] 기존 검색 지표와 Ragas 점수 분리, 사후 근거 결과 구분
- [ ] 외부 API 미사용 및 기존 서비스 회귀 검증
- [ ] 재현 가능한 실행 명령, 기준 리포트, 변경 후 비교 절차

지속 성과: 변경 전후 품질 변화, 검수 일치율, 평가 실패율을 반복 기록. 실제 답변 정확도와 자동 점수를 혼동하지 않는다.
