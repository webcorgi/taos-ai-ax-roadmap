# AX-04 — 직접 사내 MCP 서버 개발

목표: AI 클라이언트가 사내 기능을 표준화된 도구로 읽기 전용 사용. 기존 MCP를 연결해 쓰는 경험과 서버를 만드는 경험을 구분한다.

## 실행
1. 공식 MCP SDK 및 현재 transport/authorization 규격 확인. 독립 서비스, 최초 stdio/localhost로 단일 승인 개발자만 사용. RAG 본체 API 유지. 실제 API 계약 확인 후 최소 도구 `search_company_docs`와 `get_project_status` 설계(상태 원본은 승인된 BMAD/프로젝트 요약). 추가 도구는 필요할 때만.
2. 도구별 입력 JSON Schema, 허용 범위·프로젝트, 제한된 검색 건수, 출력 크기, 시간 제한, 오류 코드, 출처, 읽기 전용 권한 명시. 범위와 인증은 서버에서 강제. 임의 shell/SQL/파일 경로/URL/외부 HTTP 도구 금지.
3. 승인된 문서와 합성 상태로 두 도구 구현. 모델 없이 MCP Inspector/SDK 테스트로 discovery/call/schema 오류/타임아웃/권한 실패 확인. 사용자의 Codex/Claude Code 실제 환경과 지원 방식 확인 후 승인된 클라이언트에서 테스트. 자격증명은 환경별 비밀 저장.
4. RAG 문서 권한이 단일 사용자이므로 이 단계는 공유 서버가 아니다. 향후 다중 사용자 인증·접근 제어·토큰 범위·감사·세션 격리 및 MCP 최신 보안 규격을 별도 설계한다.

## 완료 기준
- [ ] 2개 읽기 전용 도구 등록·직접 호출·출처와 출력 검증
- [ ] 비정상 입력/범위 밖 요청/권한 부족/장애의 차단 또는 안전 실패
- [ ] 승인된 AI 클라이언트 1개 실제 연결 및 재현 방법 확보
- [ ] 읽기 전용, 내부 접근, 로그 비식별 및 서버 중단 시 기존 RAG 보존

지속 성과: 업무 조회 성공률·도구 호출량·오류·사람 개입을 기록. 모델의 도구 선택 평가는 AX-05에서 한다.
