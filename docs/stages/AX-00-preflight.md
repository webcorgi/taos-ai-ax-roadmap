# AX-00 — 읽기 전용 사전 점검 (첫 단계)

목표: 이미 구축한 RAG와 실제 서버 상태를 파악하고 Langfuse 연동 전 기준값과 안전한 테스트 환경을 확보한다. **이 단계에서는 설치·기동·배포·운영 설정 변경을 하지 않는다.**

## 실행 순서
1. `RAG` 저장소 접근 및 실제 체크아웃 경로 확인. `git status --short`, `git rev-parse HEAD`, `git branch --show-current`, AGENTS/README/compose/requirements.lock/운영 문서 확인. 사용자 변경이 있으면 보존한다.
2. 승인된 환경에서 OS/CPU/RAM/디스크/GPU, Docker/Compose 버전, 컨테이너 상태, CPU/RAM/볼륨/포트 사용량을 읽기 전용 조회. 예: Linux `free -h`, `df -h`, `docker compose ps`, `docker stats --no-stream`, `ss -lnt`, GPU 존재 시 `nvidia-smi`. 환경에 따라 명령을 바꾸고 비밀값은 출력하지 않는다. 운영 전체 프로세스 환경/compose 해석 결과에는 비밀이 있을 수 있어 무단 출력 금지.
3. 기존 서비스 상태를 승인된 읽기 전용 health API로 확인. RAG 실제 주소 확인 후 `/health/ready`, 기존 `tests/` 및 평가 스크립트의 사용 방법을 확인한다. 기존 테스트 실행이 운영 DB/자원에 영향을 주는지 먼저 검토. 실제 생성 기준 측정은 격리 환경에서 승인된 샘플로만 수행한다.
4. 기존 30개 질문·84% 검색 기준·9건 생성 동작 결과 확인. 신규 독립 평가 세트 확보 계획 작성. 기존 문서 수집 범위가 적절한지 확인하고 인증정보·개인정보가 포함된 자료는 승인/제외 전 추가 수집하지 않는다.
5. Langfuse 자체 호스팅의 최신 공식 요구사항·라이선스·네트워크·보관 정책 조사. 운영 서버에 자원 부족이면 별도 승인된 개발 PC/VM 계획 작성. Cloud 우회 금지. 실행 위치, 접속 방식, 네트워크 격리, 필요 자원과 롤백 방법을 결정한다.
6. `records/AX-00-YYYYMMDD.md`에 기준값, 미확인 정보, 사용할 테스트 환경, 실행 가능한 다음 한 단계, 승인 범위 기록. 진행 상태 갱신 및 검사.

## 완료 기준
- [ ] 대상 SHA/저장소 지침/기존 상태 확인
- [ ] 실제 자원·포트·환경 및 기존 서비스 확인
- [ ] 평가 기준과 보안/승인 범위, 자료 제외 기준 확인
- [ ] Langfuse 격리 실행 계획 및 기존 RAG 보존·롤백 계획 확보
- [ ] 기록과 상태 검사 통과
