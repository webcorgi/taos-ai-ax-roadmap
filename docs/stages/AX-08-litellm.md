# AX-08 — LiteLLM: 공통 모델 게이트웨이 (조건부)

기존 RAG/Dify/업무 AI의 모델 연결이 늘어날 때만 검토한다. 모델 하나·사용자 하나라면 복잡성 증가가 더 클 수 있다.

## 실행
1. 실제 모델/프로젝트 수, 인증·사용량·라우팅 문제를 계측. 도입 이유가 약하면 사용자 승인으로 DEFERRED; 기술 비교 실습은 격리에서만.
2. 공식 LiteLLM 버전/라이선스/가상키·한도·로그 설정 검토. 내부 Ollama 및 승인된 모델만 등록. API 호환성, alias, 인증, 프로젝트별 접근·rate limit, 실제 가능한 예산 제한을 설정하고 기능/라이선스 제약 기록. 외부 fallback 기본 금지.
3. 합성 데이터로 키 분리·허용 모델·제한 초과·모델 장애·fallback 차단·키 폐기 테스트. 내부 문서 전송 및 요청 원문 로그 차단을 직접 검증. 토큰/비용이 제공되지 않으면 미측정으로 저장.
4. 기존 앱은 플래그/설정으로 선택적 경로 전환. 장애 시 기존 로컬 경로 복구; 권한 정책을 우회하는 fallback 금지. 한 서비스 격리 전환과 원복 검증.

## 완료 기준
- [ ] 채택 필요성·승인 또는 보류 사유/승인 기록
- [ ] 도입 시 키·한도·모델 허용 정책·장애 및 외부 전송 차단 검증
- [ ] 실제 경로 전환·원복, 기존 동작과 측정 비교

지속 성과: 모델 접근 정책·호출량·오류·한도 차단 및 실제 비용 관리. 미도입이면 운영 성과로 표기하지 않는다.
