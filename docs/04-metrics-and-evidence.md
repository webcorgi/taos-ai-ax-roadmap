# 지속적인 AX 성과 측정

## 공통 측정 원칙

도구 설치 수, 코드 줄 수, AI의 자기보고는 업무 성과가 아니다. 도입 전 동일 업무 기준을 먼저 기록하고 도입 후 같은 조건으로 비교한다. **기존 업무 → 사람이 정한 기준 → AI 위임 범위 → 실제 검증 → 반복 효과**를 한 단위로 기록한다. 사용자/담당자가 정한 목표와 분모를 고정하고 결과를 보고 기준을 바꿔 통과시키지 않는다.

| 지표 | 정의 |
|---|---|
| 업무 처리량 | 정해진 기간에 실제 완료된 업무 수 (샘플/시험 제외) |
| 업무 처리 성공률 | 기준에 맞게 완료된 업무 / 시도된 업무. 실패·보류·취소를 따로 표시 |
| 사람 개입률 | 사람 수정/승인이 필요했던 업무 / 전체 시도 업무. 필수 승인과 오류 개입 구분 |
| 사람 판단 일치율 | 기준이 있는 검수에서 일치한 업무 / 실제 사람이 검수한 업무 |
| 순수 작업시간 절감 | 동일 업무의 기존 수동 시간 - 도입 후 사람 작업·검수·재처리 시간. 시스템 경과 시간 별도 |
| RAG Recall@5 (근거 포함) | 사전 지정 근거가 Top-5에 포함된 질문 / 근거가 있는 고정 질문 |
| 답변 품질 | 근거 충실도, 관련성, 출처 일치, 보류 적절성을 지표별 분리. LLM 평가와 사람 평가 분리 |
| 안전 | 권한 위반/외부 전송/허용되지 않은 실행의 차단 결과. 시험만으로 위험 제로 주장 금지 |
| 성능 | p50/p95, 오류율, timeout, TTFT(첫 응답 기준 명시), tokens/s, CPU/RAM/GPU, 비용(확인 가능한 경우) |

## 관측 계획 (제안, 사전 승인 후 적용)
- 도입 전 최소 1회 기준 측정, 가능하면 동일 업무 20~30건을 표본으로 비교. 독립 질문 세트는 최소 50건 목표(실제 업무 질문 포함, 승인된 자료만). 표본이 부족하면 실제 수치만 보고하고 확대한다.
- 운영 적용 후 2~4주 또는 업무 주기에 맞춰 누적 지표를 확인. 단기 시험 수치와 실제 운영 수치를 섞지 않는다. 월별 집계 기준은 팀의 업무량을 고려해 정한다.
- 변경 전후 모델/버전·프롬프트·데이터 스냅샷·환경을 기록. RAG 기존 지정 근거 84%, 사후 평가 100%는 분리 유지.
- 자동 평가 모델의 점수는 인간 정답률이 아니다. 표본 사람이 검토하고 평가자 불일치·실패를 기록. 점수 평균에 품질이 낮은 항목이 숨지 않도록 질문 유형별 결과도 저장한다.
- 비용 미측정 시 `null` 또는 미측정. 로컬 모델에 가상의 API 단가를 적용하지 않는다. 텍스트 bytes 감소를 토큰·비용 감소로 바꾸지 않는다.

## 포트폴리오 공개용 정리
- 대표 사례에 통합: RAG 추적/평가/갱신, AI 업무 에이전트, 보고 자동화, 공통 AI 운영. 도구 하나당 포트폴리오 사례를 억지로 만들지 않는다.
- 공개할 수 있는 집계 수치와 합성 캡처만 사용하고 회사 승인 범위를 확인한다.
- 문장 양식: "[반복 업무]에서 [오래 걸리는 판단]을 골라, [사람이 정한 기준]을 적용하고, AI에게는 [위임 범위]까지만 맡겼습니다. [기간·분모] 중 [검증 결과]를 확인했고, [반복 운영 지표]를 측정합니다."
- 아직 미사용이면 "격리 검증 완료, 운영 적용 전". 실제 성과가 확인되면 기간·환경을 포함해 수치 갱신.
