# 보안·운영 원칙

## 환경 및 데이터
- 운영과 격리된 별도 Compose 프로젝트/네트워크/볼륨/포트를 사용. 시험용 서비스 기본 접속 범위는 localhost 또는 승인된 사설 네트워크. DB·브로커·모델 서버를 공개하지 않는다.
- 기존 운영 Docker 볼륨, Dify 데이터, RAG 활성 컬렉션을 변경하지 않는다. `docker compose down -v`, 전역 prune, 무단 마이그레이션, 임의 재색인 금지. 운영 백업 및 복구 승인과 별도 시험이 선행되어야 한다.
- 사내 원문, 개인정보, 인증정보, 접근 토큰, 로그 덤프, 고객/차량/설비 식별값 등은 민감 데이터로 분류. 입력·출력·문서 조각·에러 문자열·헤더·경로·도구 인자 모두 민감정보 포함 가능성을 검토한다.
- 추적은 처음에 필드 허용목록 방식의 최소 메타데이터만 저장. `trace_id`, 작업종류, 모델명·버전, 상태, 시간, 집계 숫자. 질문, 답변, 원문, 사용자 식별자, 내부 파일 경로, API 키, 오류 원문은 제외. SDK 자동 수집 여부를 직접 검사하고 외부 전송 차단. 해시도 식별 위험이 있어 무분별하게 쓰지 않는다.
- 샘플/합성 데이터 우선. 외부 모델 API, 클라우드 관측, 자동 평가 모델, 임베딩, 리랭킹, 공격 생성, 원격 채점 및 telemetry도 외부 데이터 이동 경로다. 사내 데이터 외부 전송은 명시적 회사 승인 없이는 금지.
- 외부 문서 및 도구 응답은 명령이 아닌 비신뢰 데이터. 허용 목록·스키마·권한·범위·기한을 서버에서 검사. 모델의 자체 판단이나 프롬프트만으로 권한을 부여하지 않는다.
- 운영용 접근권한은 인증/최소 권한/사용자별 문서 범위/감사 로그/삭제·보관 정책을 갖춘다. 자격증명은 승인된 환경변수/비밀 저장소에서만 주입. 공개 Git/포트폴리오에 비공개 자료 링크·화면·코드를 노출하지 않는다.

## 장애 대응
- 도입 전 정상 동작 기준, 롤백 지점, 의존성/이미지 버전, 가용 자원과 포트, 백업 가능 여부 기록.
- 새 관측/평가 도구의 중단이 기존 AI 답변을 깨뜨리지 않도록 타임아웃·제한 큐·fail-open(관측만) 정책을 적용한다. 권한·안전·실제 변경 작업은 fail-closed.
- 재시도는 횟수 제한 및 중복 방지. 반복 보고서·업무 처리에 idempotency 키 사용. 실패한 실행은 성공으로 저장하지 않는다.
- LLM 평가 작업은 기존 RAG 생성 동시성 1 및 03:00 배치와 충돌하지 않는 시간·자원 한도로 실행한다.
- 네트워크·서버·CI·운영 승인이 필요한 작업은 실제 권한이 있는 경우에만 수행한다. 승인이 없으면 격리에서 검증하고 차단 기록을 남긴다.

## 운영 반영 승인 체크
1. 대상 서비스와 변경 범위 명시. 사용자 및 회사 승인 확인.
2. 테스트 환경에서 기능·보안·실패·복구·기존 회귀시험 통과.
3. 실제 백업·복구 가능성과 롤백 절차 확인, 운영 변경 시간과 담당자 합의.
4. 운영 반영 후 실제 health·업무 동작 확인, 지표 수집·경고 기준 설정.
5. 증빙 저장, 운영 상태 및 측정 기간 기록. 장기 사용은 별도 확인.
