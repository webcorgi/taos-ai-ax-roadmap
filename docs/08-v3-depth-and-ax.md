# V3 기술 깊이·FDE·기업 AX 학습 계약

기준일 2026-11-27. 기존 22개 단계와 상태 스키마 v2 유지. 이 문서는 모든 단계의 추가 필수 기준이다. AI 활용 개발 속도와 사용자 독립 역량은 별도 평가한다.

## 1. 매 단계 학습 루프
1. 문제 발견: 업무 담당자·빈도·현재 흐름·불편·기준선 확인. 도구 설치 자체가 목적이 아니다.
2. 원리: 입력→처리→출력, 내부 핵심 원리, 제약, 실패 원인을 3~5문장과 코드 위치로 설명.
3. 최소 실습: 작은 격리 코드로 동작을 재현하고 사용자가 직접 핵심 설정/코드를 바꾼다.
4. 적용: AI를 적극 사용해 기존 시스템 연동 또는 합성 환경 구현. 승인 경계 유지.
5. 실패: 오류를 주입하고 로그/trace로 원인을 좁혀 수정·재시험. 실제 운영 장애 주입 금지.
6. 독립 검증: 아래 기준을 사용자 본인이 수행. 정답은 제출 이후 공개.
7. 성과: 기준선과 비교하여 품질·시간·비용·사용률을 기록. 실제/합성/추정 구분.
8. 복습: 1·3·7일 후 기억에서 설명하고 변형 과제 수행. 일정은 목표이며 이후 단계와 병행.

## 2. 독립 검증 기준
각 항목 PASS/FAIL/NOT_RUN과 증거를 단계 보고서에 기록한다.
- 원리: 자신의 말로 원리와 한계를 설명하고 데이터 흐름을 그리거나 설명.
- 구현: AI 생성 없이 핵심 코드 또는 설정을 직접 수정하고 예상 결과 및 테스트 확인. 공식 문서 참고는 허용하며 도움 범위 기록.
- 장애: 정답 미제공 실패 사례에서 원인 가설→로그 확인→수정→재시험.
- 판단: 대안 두 가지 이상의 장단점과 선택 기준, 비용·보안·운영 위험 설명.
- 적용: 해당 단계의 업무 문제, KPI, 실패 시 사람 개입과 검증 방식 설명.
AX-00/AX-21 등 비구현 단계는 코드 대신 현황·측정·검증 계획의 오류를 찾아 직접 수정하는 동등 과제로 평가한다. 운영 승인·실제 고객 접촉이 없는 경우 모의 검증과 실제 검증을 구분한다.
모든 해당 필수 항목 PASS와 기존 기술 기준 충족 시만 신규 VERIFIED. 힌트로 해결한 경우 새로운 변형 과제로 독립 검증. 사용자가 응답하지 않으면 IN_PROGRESS. 에이전트는 사용자의 응답을 대신 작성하지 않는다. 지연 복습·외부 검토는 별도 숙련 증거이며 최초 단계 진행을 영구 차단하지 않는다.

## 3. 역할
Tutor(개념), Architect(설계·대안), Builder(구현), Reviewer(테스트·보안), Examiner(독립 평가), AX Consultant(업무·성과)를 순서에 맞게 분리한다. 한 에이전트가 역할을 전환해도 되며 별도 서비스 설치 불필요. 평가자는 구현 결과만 보고 사용자 역량을 추정하지 않는다.

## 4. FDE·AX 실무 역량
프로젝트 시작 전 다음을 기록한다. 동일 업무에 이미 검증한 분석은 재사용하되 바뀐 조건은 갱신한다.
- Discovery: 업무 담당자 인터뷰(불가 시 모의 명시), 문제와 요구사항, 성공/실패 조건.
- As-Is/To-Be: 현재 업무 흐름과 개선 흐름, 제거·단순화·규칙 자동화·AI 대안 비교.
- 제약: 데이터 품질·권한·보안·예산·시스템 통합·운영 책임·승인 및 인수 조건.
- 성과: 기준선, 측정 기간, 목표, 실제 사용률, 오류/재작업률, 시간 및 운영비.
- ROI: 기간 내 편익=검증된 절감 시간×합의된 시간 단가+기타 입증 편익. 순편익=편익−구축·운영·검수·교육 비용. ROI=순편익/총비용×100(총비용 0이면 산정 불가). 예상과 실측 분리, 시간 절감을 현금 절감으로 자동 간주 금지.
- 확산: 담당자 교육, 피드백, 승인/예외 처리, 운영 인수, 부서별 확장 및 중단 기준.
- 경영진 제안: 문제·대안·예상 효과·비용·위험·승인 요청을 1페이지로 작성.

## 6. 검증 및 이관
AX-20에는 기존 실제 승인 파일럿 외 낯선 합성 기업 과제를 추가한다. 정답 없는 요구사항과 장애를 바탕으로 설계·핵심 수정·검증·설명까지 사용자 수행. 단기/중기/장기 끝에 채용 게이트 재평가. 실제 전문가 리뷰는 가능할 때 요청하고 미확인 시 명시한다.
기존 VERIFIED 기록은 소급 변경하지 않는다. V3 증거가 없으면 독립 숙련 미확인으로 보고 후속 복습에서 검증한다. state 파일과 기존 단계 ID 및 스크립트의 스키마는 변경하지 않는다. V3는 문서·보고서 기반 학습 계약이며 자동 채점기가 아니다. 실습 8주 목표와 숙련 완료 시점은 별개다.
